## 📋 Executive Summary

The sm-js-bc v0.4.0 release (2025-12-08) includes major new features and API consistency improvements to align with Bouncy Castle Java, bringing the overall API consistency score from 91% to 97%. This document outlines the plan to align the Python implementation (sm-py-bc) with these improvements.

### Key Changes in sm-js-bc v0.4.0

#### API Consistency Improvements (v0.3.1)
1. **SM3Digest**: Added `reset(Memoable)` method overload for state restoration
2. **SM2Engine**: Added `SM2Engine.Mode` static property for Java-style enum access
3. **SM2Signer**: Added `createBasePointMultiplier()` and `calculateE()` protected methods
4. **Documentation**: Comprehensive API compatibility documentation

#### New Features (v0.4.0)
1. **HMAC-SM3**: Message authentication code based on SM3 digest
   - HMac class with standard API
   - Full bc-java compatibility
   
2. **ZUC Stream Cipher**: 祖冲之序列密码算法 (for 3GPP LTE/5G)
   - ZUC-128 Engine
   - ZUC-256 Engine  
   - ZUC-128 MAC
   - ZUC-256 MAC
   
3. **PKI Support**: Complete public key infrastructure
   - ASN.1 encoding/decoding (DER format)
   - PKCS#8 private/public key encoding (PEM/DER)
   - PKCS#10 certificate signing requests (CSR)
   - X.509 certificates (generation, parsing, validation)
   - Certificate chains and validation
   - Certificate Revocation Lists (CRL)
   - Subject Alternative Names and other extensions

### Goals for sm-py-bc

**Phase A: API Consistency (Quick wins - v0.2.0)**
- ✅ Implement equivalent Python API improvements
- ✅ Maintain 100% compatibility with Bouncy Castle Java  
- ✅ Keep existing functionality intact
- ✅ Update documentation

**Phase B: New Features (Major features - v0.3.0+)**
- ⏳ Implement HMAC-SM3 (Priority: High)
- ⏳ Implement ZUC stream cipher (Priority: Medium)
- ⏳ Implement PKI support (Priority: Future)

**Scope Decision**: This task will focus on Phase A (API consistency) and HMAC-SM3 from Phase B, as these are the most impactful and align with current codebase structure.

## 🔍 Key Differences from sm-js-bc v0.4.0

### Differences to Implement

1. **SM3Digest.reset() overload**: TypeScript uses optional parameter, Python will use same pattern
2. **SM2Signer.calculateE()**: Need to extract and rename method in Python

### Differences to Document (Acceptable)

1. **Naming Convention**: Python uses snake_case (e.g., `get_algorithm_name()`) vs Java/TS camelCase (e.g., `getAlgorithmName()`)
2. **No CryptoServicePurpose**: This is Java BC-specific, not needed in Python
3. **Type System**: Python uses duck typing and type hints, Java/TS use strict typing
